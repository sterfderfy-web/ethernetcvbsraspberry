# CVBS Ethernet Raspberry

Превращает Raspberry Pi в проводную IP-камеру: USB CVBS → H.264 → RTSP. Веб-панель регулирует яркость, контраст, цветность, гамму, шумоподавление и резкость; показывает контрольный кадр и сохраняет настройки. RAM-патч снятия отсечки слабого видео протестирован на плате видеозахвата **MacroSilicon MS2106E**, указанной владельцем.

**Адрес камеры: 192.168.144.21. Видео: `rtsp://192.168.144.21:554/live`. Настройки карты видеозахвата и изображения: `http://192.168.144.21:8080`.** Это один одноплатник и один IP; порт 554 передаёт видео, порт 8080 открывает настройки в браузере.

Протестированный захват: **MS2106E**, USB VID:PID `534d:0021`, serial `20200909`, имя USB `MACROSILICON AV TO USB2.0`. Утилита ms-tools автоматически определяет эту плату как **MS2107**; это диагностическое обозначение в утилите, а не переименование физической платы. Маркировка MS2106E приведена по уточнению владельца, физический чип удалённо не осматривался. Совместимость RAM-патча ограничена проверенной прошивкой (SHA256 ниже); одного названия MS2106E/MS2107 или VID:PID недостаточно.

## Установка одной командой

Нужна **64-битная Raspberry Pi OS / Debian с systemd и NetworkManager**, Ethernet и USB-захват MacroSilicon `534d:0021`. Пакет рассчитан на Raspberry Pi 5 и захват с serial `20200909`, проверенные в исходном проекте. Вход SSH заранее включите при записи ОС. Установщик не создаёт SSH-пароль и не заменяет учётную запись.

Скопируйте архив `cvbs-ethernet-raspberry.tar.gz` на плату и выполните:

```bash
tar -xzf cvbs-ethernet-raspberry.tar.gz && sudo bash cvbs-ethernet-raspberry/install.sh
```

После публикации на GitHub:

```bash
git clone https://github.com/sterfderfy-web/ethernetcvbsraspberry.git && sudo bash ethernetcvbsraspberry/install.sh
```

В новой системе для `git clone` должен быть установлен git. Архивный вариант обходится без git. В архив включены ARM64-бинарники, поэтому Go на плате не нужен. Архив требует интернет только для отсутствующих системных зависимостей (`ffmpeg`, `v4l-utils`, `python3`, `network-manager`, `rfkill`, `util-linux`); если они уже установлены, архивная установка работает без интернета. Git-версия содержит готовый патчер и загружает официальный MediaMTX при установке с проверкой закреплённой SHA256; для этого нужен интернет и curl (устанавливается автоматически, если отсутствует).

Установщик проверяет контрольные суммы, сохраняет прежние конфигурации в `/root/cvbs-backup-*`, устанавливает службы и запускает веб-панель без пароля. Через 10 секунд в конце установки включает постоянный Ethernet **192.168.144.21/24**, без шлюза, отключает Wi-Fi и Bluetooth. SSH через прежнюю сеть разорвётся. После установки перезагрузите плату командой `sudo reboot`, чтобы отключение встроенных радиомодулей применилось на этапе загрузки. Подключайтесь по Ethernet из подсети `192.168.144.0/24`.

Изменить параметры при установке:

```bash
sudo env CVBS_IP=192.168.144.21/24 CVBS_INTERFACE=eth0 CVBS_SERIAL=20200909 bash install.sh
```

Сохранить текущую сеть / радиомодули при проверке: `sudo bash install.sh --keep-network --keep-radios`. Другая плата ARM64 требует `--keep-radios`; совместимость видеоформата и прошивки захвата проверяется отдельно. Другой serial не означает совместимую прошивку: RAM-патч всегда проверяет исходный код по SHA256 и откажется от записи при несовпадении.

## Адреса и коррекция

| Назначение | Адрес |
|---|---|
| Видео для пульта, QGC или VLC | `rtsp://192.168.144.21:554/live` |
| Настройки карты захвата MS2106E и изображения в браузере | `http://192.168.144.21:8080` |

Панель открывается без логина и пароля. Все устройства вашей локальной сети могут менять настройки и перезапускать захват. RTSP также доступен без пароля.

## Обновление через git

Если решение установлено из архива, один раз создайте рабочую копию:

```bash
sudo apt-get install -y git
git clone https://github.com/sterfderfy-web/ethernetcvbsraspberry.git
cd ethernetcvbsraspberry
bash update.sh
```

Если копия уже есть, для первого перехода со старой версии:

```bash
cd ethernetcvbsraspberry
git pull --ff-only
bash update.sh
```

Дальнейшие обновления: `bash update.sh` из этой папки. Запускайте от владельца
рабочей копии; установщик запросит sudo. Скрипт отказывается обновлять копию с
локальными изменениями и допускает только fast-forward ветки main. Сохраняются
настройки изображения, выбранное устройство, текущая сеть и радиомодули.
Службы временно останавливаются. Резервная копия конфигурации: `/root/cvbs-backup-*`.
При прерванной установке устраните причину и повторите `bash update.sh`:
он повторяет установку даже при неизменившемся commit. Автоматического отката нет.

## Диагностика и USB-сброс

Панель опрашивает состояние каждые 5 секунд: подключение USB-захвата, службы,
число кадров с запуска, FPS, пропуски/дубли, скорость кодирования, возраст
статистики, нагрузку системы и последние строки журнала. «Проверить изображение»
пробует декодировать кадр RTSP с ограничением времени. Полученный кадр не доказывает
наличия полезного аналогового сигнала: плата может выдавать чёрный кадр или шум.
Оцените контрольный кадр визуально.

«Перезапустить USB-плату захвата» запускает отдельную службу `cvbs-reset`:
проверяет USB-идентичность настроенного видеоустройства, останавливает RAM-патч
с проверкой его восстановления, останавливает захват, выполняет USBDEVFS_RESET,
затем запускает захват и патч. Перезагрузка Raspberry Pi не требуется.
Это USB-сброс, а не физическое отключение питания; при аппаратном зависании
может потребоваться переподключение USB. Результат и ошибки видны в диагностике
и `journalctl -u cvbs-reset`. Успешный сброс сам по себе не подтверждает видео.

## Работа с коррекцией

Измените ползунки, нажмите **«Применить и сохранить»**, затем сравните кадр и изображение на реальном пульте. Во время применения захват перезапускается, возможен короткий перерыв. Браузер показывает отдельный JPEG-кадр по кнопке, непрерывное видео смотрите через RTSP. «Исходный профиль» возвращает согласованный профиль коррекции исходной установки; он применяется после нажатия сохранения. Адрес страницы совпадает с IP камеры, отдельный IP не требуется. В панели используется порт 8080.

Настройки: `/etc/cvbs-camera/settings.json` и `image.env`. Изменения действуют для всех RTSP-клиентов. Параметры ограничены диапазонами, команды от пользователя не выполняются. При ошибке перезапуска предыдущие настройки восстанавливаются.

## Службы и проверка

```bash
systemctl status cvbs-rtsp cvbs-capture cvbs-weak-video cvbs-panel
sudo bash /opt/cvbs-camera/check.sh
sudo journalctl -u cvbs-panel -u cvbs-capture -u cvbs-weak-video -n 80 --no-pager
```

H.264 Baseline 720×480, заданные 25 кадров/с, veryfast/zerolatency, 2.5 Мбит/с (максимум 3). RTSP TCP/UDP, RTP 8000, RTCP 8001. Коррекция применяется перед H.264. Остальные протоколы MediaMTX отключены.

Снятие отсечки перенесено из локального проекта ms-tools. Патч меняет **только RAM**, EEPROM не перепрошивается. Перед записью проверяется SHA256 исходных 1191 байта кода: `40a78e46954c9050a72896f44febd26dcf8559bd659a4489c4feb792936c4a10`. Сохраняются код и регистры, выполняются проверки записи и отката. Служба повторяет запуск после USB-переподключения; через 8 часов рабочий процесс делает откат, затем служба применяет патч снова. Журналы: `/var/lib/cvbs-patch/`, текущая папка указана в `current-run`.

Без устойчивой CVBS-синхронизации возможны редкие шумовые кадры и паузы. Стабильные 25 кадров/с при «снеге» не гарантируются, искусственный снег не генерируется. Патч не исправляет кабель, питание или отсутствующий аналоговый сигнал.

## Что проверено

- Ранее на реальной Raspberry Pi 5 проверены RTSP, постоянный адрес, отключение Wi-Fi/Bluetooth после перезагрузки и применение/полный откат RAM-патча. Контрольные суммы кода до и после отката совпали.
- Для новой панели локально проверяются HTTP-аутентификация, защита POST от сторонних страниц, ограничения параметров, сохранение и возврат конфигурации при ошибке службы; процессы FFmpeg/systemd в этих тестах заменены имитациями.
- **Новый общий установщик и веб-панель пока не проверены на Raspberry:** плата недоступна во время подготовки 10.10.2026. Запуск службы сам по себе не подтверждает видеосигнал. Нужны установка на плату и сравнение изображения на пульте.

## Отключение и возврат

```bash
sudo systemctl disable --now cvbs-panel
sudo systemctl disable --now cvbs-weak-video  # выполняет откат RAM
sudo systemctl disable --now cvbs-capture cvbs-rtsp
```

Прежние файлы сохранены с полной структурой путей в `/root/cvbs-backup-*`. Для возврата восстановите нужные файлы, выполните `sudo systemctl daemon-reload`, затем перезапустите службы. Для возврата радиомодулей восстановите boot/config и снимите mask с `bluetooth`/`hciuart`, включите радио NetworkManager/rfkill и перезагрузитесь. Сеть возвращайте через проводное соединение или локальную консоль.

## Исходники и лицензии

- `panel.py`, `index.html`, `install.sh`, `services/` — панель и установка.
- `ms-tools-src/` — полные исходники использованной версии патча с Linux-адаптацией.
- `binaries/ms-tools-arm64` — Linux ARM64, pure Go HID; SHA256 `e3e279bddc4d6a33e62236aee104b0fc0d2a1291735149c329c116971ab8cd32`.
- [MediaMTX v1.21.1](https://github.com/bluenviron/mediamtx/releases/tag/v1.21.1) — официальный ARM64-архив; SHA256 `6a3aa635fb60ea9b8d566ec306f0a42ff1b6b52a3942bc2baffbe55880d4c3dd`.
- ms-tools: Copyright (c) 2021 Bertold Van den Bergh, MIT; лицензия сохранена в `ms-tools-src/LICENSE`. MediaMTX — MIT, лицензия в архиве. Остальной код этого пакета — MIT, см. `LICENSE`.

Пересборка патча (Go): `cd ms-tools-src && GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -tags puregohid -o ../binaries/ms-tools-arm64 ./cli`. После изменений обновите `SHA256SUMS`.

Локальные проверки: `python3 -m unittest discover -s . -p 'test_*.py'`; `bash -n install.sh capture.sh check.sh cvbs-patch-run cvbs-patch-stop`. Два теста отката ms-tools требуют локальный файл исходного кода RAM через переменную `MS_TOOLS_TEST_FIRMWARE`; без него они пропускаются. Дамп карты в публичный пакет не включён. Автоматическая проверка в GitHub Actions не заменяет испытания видеозахвата.
